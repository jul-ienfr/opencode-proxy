## 2. Définition de « usable »

Une station est **client-usable** si :

1. tunnel `connected` ou `degraded` ;
2. probe santé récente OK ;
3. bucket upstream **200** pour `deepseek-v4.1-flash-free` ;
4. pas de 429 dans la fenêtre courante.

Le dashboard expose `client_usable = station_usable && model_usable`.

### États

| État | Signification |
|---|---|
| `ACTIVE` | 200 récent + headroom, sert le trafic |
| `WARM` | 200 récent, validée, prête à promouvoir |
| `COOLING` | 429, `reset_at` futur, re-probe au reset |
| `DEAD` | 2 échecs consécutifs, quarantaine longue |
| `UNVALIDATED` | issue de l'inventaire, pas encore re-testée |

### Sélection

1. `ACTIVE` avec le meilleur score (succès × latence × fraîcheur) ;
2. sinon `WARM` ;
3. sinon `COOLING` dont `reset_at <= now` ;
4. sinon `UNVALIDATED` (batch de validation).

## 12. Procédure de re-probe (egress → hostname)

**Principe** : une egress IP est une IP NAT ; on ne peut pas la « contacter » comme un serveur. On bind un **hostname**, on observe l'egress produite, et on enregistre le couple `host ↔ egress`. Le mapping se découvre, il ne se lit pas dans l'API.

### Méthode A — `fresh_chain.py` (robuste, recommandée)

1. Générer une liste de hostnames **non actifs** (exclure `al36`, `al37`, `al41`, `al45`, `al46`, `al73`, `al74`, `al75` et les hosts des 6 stations).
2. Lancer sur la station 7 (spare, 10 devices) :
   ```powershell
   python scripts/fresh_chain.py --station 7 --transport openvpn-tcp `
     --candidates logs/reprobe_hosts.json --max 20 --rebind-limit 2 --claims
   ```
3. Le log `logs/fresh_chain_7.log` contient `bind <host>` puis `egress <ip>`.
4. Mettre à jour `ip_state` avec le parseur :
   ```powershell
   python C:\Users\julie\AppData\Local\Temp\opencode\recover_hostnames.py
   ```
5. Répéter par batchs de 20 ; les hostnames 200/429 sont enregistrés, les egress inédites sont ajoutées.

### Méthode B — control API (rapide, mais station stable requise)

```powershell
# basculer la station 7 sur un hostname non actif
docker exec opencode-vpn-7 sh -c 'wget -q -O - -T 20 --header="X-API-Key: $VPN_CONTROL_API_KEY" --method=PUT --body-data='"'"'{"provider":{"server_selection":{"hostnames":["<host>"]}}}'"'"' http://127.0.0.1:8000/v1/vpn/settings'
# attendre le tunnel puis lire l'egress
curl.exe -s --max-time 20 --socks5-hostname 127.0.0.1:1086 https://api.ipify.org
```

La méthode B est plus rapide (pas de recreate) mais la station 7 doit être stable et le hostname **non actif**.

### Limites
